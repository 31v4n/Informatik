Modelle, Schlüssel, Beziehungen, ER-Diagramme & Normalisierung

Datenbankarten

Relationale Datenbanken

Daten werden in Tabellen mit Zeilen und Spalten gespeichert. Tabellen werden über Beziehungen verbunden und meistens mit SQL abgefragt.

Beispiele: MySQL, PostgreSQL, MariaDB

NoSQL-Datenbanken

Flexible Datenstrukturen für große Datenmengen und horizontale Skalierung. Ideal für unstrukturierte Daten.

Beispiele: MongoDB, Redis

Graph-Datenbanken

Speichern Daten als Netzwerk aus Knoten und Verbindungen. Perfekt für komplexe Beziehungen.

Beispiel: Neo4j

In-Memory-Datenbanken

Daten liegen direkt im Arbeitsspeicher und ermöglichen extrem schnelle Zugriffe.

Einsatz: Echtzeitanwendungen

Primärschlüssel

Identifiziert jeden Datensatz eindeutig. Keine Duplikate und niemals leer.

Beispiel: Kundennummer

Fremdschlüssel

Verweist auf den Primärschlüssel einer anderen Tabelle und erstellt Beziehungen.

Bestellung → Kunde

Kandidatenschlüssel

Kann einen Datensatz eindeutig identifizieren. Ein Kandidat wird später zum Primärschlüssel.

Sekundärschlüssel

Wird für Suche oder Sortierung genutzt, ist aber nicht der Hauptidentifikator.

Beziehungen

1 : 1

Ein Datensatz gehört genau zu einem anderen.

Abteilungsleiter ↔ Abteilung

1 : N

Ein Datensatz kann mehrere andere besitzen.

Kunde → viele Bestellungen

M : N

Viele Datensätze können vielen anderen zugeordnet werden.

mehrere Studenten ↔ mehrere Vorlesung

Entitätstyp

Objekte oder Personen, über die Daten gespeichert werden. In der Datenbank entspricht dies einer Tabelle.

Attribute

Eigenschaften einer Entität. Der Primärschlüssel wird unterstrichen dargestellt.

Beziehungen

Zeigen Verbindungen zwischen Entitäten. Zum Beispiel: Kunde erstellt Bestellung.

Normalisierung

1. Normalform (1NF)

Alle Werte müssen atomar sein. Keine Listen oder mehrere Werte in einer Zelle.

Eine Zeile = ein eindeutiger Datensatz

2. Normalform (2NF)

Die 1NF muss erfüllt sein. Nicht-Schlüsselattribute dürfen nicht nur von einem Teil eines zusammengesetzten Schlüssels abhängen.

Tabellen werden bei Bedarf getrennt

3. Normalform (3NF)

Keine transitiven Abhängigkeiten. Attribute dürfen nur vom Primärschlüssel abhängig sein.

Keine unnötigen Abhängigkeiten zwischen Nicht-Schlüsseln
